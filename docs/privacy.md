# Privacy and sharing

## Local-first does not mean offline or anonymous
The backend uses Azure CLI tokens to contact Azure Resource Manager, Foundry, and Application Insights. Browser requests go through that backend. All tabs share its cloud identity and settings; there is no local administrator account, hosted/OIDC authentication, or per-user privacy boundary. Run only for trusted local users and retain loopback host binding/port publishing. [Distributed workspaces](distributed-workspaces.md) are logical groupings independent of the selected Foundry project, not hosted sharing or deployment boundaries.

Settings persist in `data/config.json` (or the selected data directory). Project identifiers, endpoints, application identifiers, and workspace metadata/notes may reveal private infrastructure or operational context. Reviewer names on local notes are self-entered, not authenticated identities. Azure CLI maintains its own credential cache, including in the Compose `azure-login` volume; tokens are not dashboard configuration. Protect both data and CLI volumes with local access controls. Stopping the app does not delete them.

Telemetry may contain prompts, model outputs, tool arguments/results, errors, user identifiers, and confidential business data. The original single-agent views expose recorded raw inputs/outputs and logs when available; they are not redacted by the distributed export feature. Obscured fields or truncated strings do not make a trace safe to disclose. Browser downloads, clipboard copies, screenshots, and saved logs have their own retention and access risks. The application is not a credential vault or a data-loss-prevention system.

## Export and import caveats
Only the distributed workspace **Download redacted trace** export uses allowlisted, pseudonymized metadata: it omits names, absolute timestamps, prompts, outputs, logs, annotations, resource IDs, and raw attributes. It retains relative timing, topology, span kinds, failure/sampling information, and token counts. These retained patterns can still identify activity or reveal operational context; pseudonymization is not an anonymity guarantee. Review the actual file before sharing. No live Azure or complete privacy/compliance validation is claimed.

Workspace configuration, local notes, raw API responses, screenshots, and other manually copied files are not this redacted trace export: they can still contain sensitive names, resource identifiers, endpoints, links, and free text. A copied local deep link also contains identifiers and requires the recipient's matching local workspace and Azure permissions; it is not a hosted shared view.

Prefer synthetic reproductions. Remove customer/personal data, tokens, tenant/subscription/project IDs, private endpoints, sensitive links, and prompt/tool content. Review nested objects and free-text notes as well as visible fields. Do not attach `config.json`, Azure CLI directories, raw traces, or container volumes to public issues. Treat externally supplied workspace definitions/files as untrusted data, not instructions to execute; verify provenance and contents before use. The [workspace guide](distributed-workspaces.md) describes versioned definition imports, which populate the editor and persist only on Save. Share only with authorized recipients under applicable organizational retention rules.

## Distribution boundary
Licensing is deferred at the owner's request; no `LICENSE` is added and no redistribution permission is implied. No remote publishing destination is selected. Source and container archives must exclude runtime data and credentials. The manual workflow builds from source rather than exporting a running container and does not upload dashboard volumes; its Actions artifacts still inherit the repository's visibility. CI fixture tests and container builds are not proof of live Azure access, compliance, or complete privacy controls.
